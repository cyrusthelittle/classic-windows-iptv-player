# Cyrus IPTV roadmap

Updated 21 September 2026; audit started 20 September. Target: the existing Windows 10/11 desktop application, with mouse and keyboard first and fullscreen support throughout. The product still identifies itself as Classic Windows IPTV Player; settle the public name before changing packaging or release links.

The goal is to make opening the app, finding something, watching it, and returning later consistently easy. Keep WPF and LibVLC; there is no evidence that a framework rewrite would address the current problems.

See the [feature, competitor, UI and mechanics audit](docs/PRODUCT_AUDIT.md) for the evidence and source links. This is an ordered backlog, not a delivery-date promise. Sizes are relative implementation effort: S = contained change, M = several connected changes, L = subsystem or multiple reviewable increments.

## Validation and delivery rhythm

For each numbered step: reproduce the problem, implement the smallest complete slice, run the relevant regression checks and Windows build, demonstrate the changed flow, then mark the step complete here. A successful compilation alone is not playback verification. Avoid a large unrelated refactor inside a feature step.

Use synthetic M3U/XMLTV/Xtream data and a local fixture server for parser/network checks; use authorized streams for final playback verification. Use an isolated data directory for integration checks. Preserve the user's normal accounts, caches and favorites.

Performance targets below are proposed budgets to measure on a recorded reference PC, not claims about current performance:

- Cached 50,000-item library usable within 3 seconds, excluding provider networking and native decoder initialization.
- Search at p95 under 300 ms after the existing debounce; canceled searches never replace newer results.
- Core UI actions respond within 100 ms; cancellation feedback appears within 250 ms even if native cleanup continues.
- Record time-to-first-frame separately from provider response and configured network buffering; compare controlled local fixtures before setting channel-zap targets.
- Soak test repeated channel changes, stream stalls, sleep/resume and multi-monitor fullscreen; record crashes, hangs, detached windows and memory growth.

For releases: a Windows CI build plus regression checks, a clean extracted portable-package smoke test, native DLL/version validation, and release notes that match implemented shortcuts and capabilities. Settle distribution/signing and update authenticity before adding automatic installation.

## Explicitly deferred decisions

- Android/iOS/macOS ports, cloud sync and a framework rewrite need a separate product decision.
- Stalker support, casting and DRM playback are not assumed requirements. Prioritize them only with actual source/device demand; the current player cannot promise support merely because a competitor lists it.

- Capture capabilities depend on provider and engine behavior. Catch-up, local recording and disk-backed timeshift are different features and remain separate steps.
