# Cyrus IPTV roadmap

Updated 3 October 2026; audit started 20 September. Target: the existing Windows 10/11 desktop application, with mouse and keyboard first and fullscreen support throughout. The product still identifies itself as Classic Windows IPTV Player; settle the public name before changing packaging or release links.

The goal is to make opening the app, finding something, watching it, and returning later consistently easy. Keep WPF and LibVLC; there is no evidence that a framework rewrite would address the current problems.

See the [feature, competitor, UI and mechanics audit](docs/PRODUCT_AUDIT.md) for the evidence and source links. This is an ordered backlog, not a delivery-date promise. Sizes are relative implementation effort: S = contained change, M = several connected changes, L = subsystem or multiple reviewable increments.

## Step 18 implementation and validation (29 September 2026)

Instant Record now works on the tuner-owned live input rather than being limited to `SharedHlsSource`: Record briefly retires playback, waits for the old provider socket to close, then retunes with one LibVLC media configured for both display and file output. Stop closes/flushed that output before restoring ordinary playback. A 250 ms socket-release grace prevents the tested provider responses from overlapping. No recorder player, URL probe, or extra provider lease is created. The container is selected from active tracks (MPEG-TS for common IPTV codecs, Matroska for broader/unknown codecs).

Validation: `RecordingRegressionChecks` **22/22** and `SharedHlsSourceRegressionChecks` **16/16** pass. The isolated production-window harness passes **73/73**: shared-HLS capture uses its existing poller; a progressive MPEG-TS live feed records through the same tuner pipeline, grows and flushes, reopens and decodes; Record and Stop each make one sequential replacement provider request, measured concurrent provider responses stay at **one**, playback returns after Stop, and no connection-budget lease is added. Windows Release build passes with 0 warnings/errors; `git diff --check` passes. Evidence is in `%TEMP%\cyrus-recording-ui-7c29e21e38a34c1781ac668a38e4b6e6\evidence.txt`.

Boundaries: the non-HLS test is synthetic progressive MPEG-TS, not an authorized real-provider session. Instant recording depends on LibVLC being able to demux and pass the active codecs into MPEG-TS or Matroska; DRM/protected inputs, provider restrictions, and unsupported codecs/muxers cannot be promised as recordable. Retuning intentionally causes a brief playback interruption, and the captured media begins/ends at the actual output handover around the button action.
