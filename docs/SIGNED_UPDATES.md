# Signed application updates

The global Settings > Updates preference **Download signed updates automatically (ask before restart)** defaults off. Existing update checks remain independent. Automatic offers are modeless so library browsing and playback controls remain available during the download. When an update is offered, Update now downloads its signed assets, verifies them, and changes to Restart to update. Cancel stops downloading/verification; Retry starts a fresh download; Later leaves the current app running. A verified stage is reused for the same offer while this process remains open. A later process currently downloads it again rather than trusting old stage metadata. Release notes and Open this release on GitHub remain available, including for older unsigned releases.

Restart is refused while a tune/playback request (including paused/buffering), multi-view window, active recording or recording transition is present. Stop playback, finish recording/close multi-view, then check for updates and choose Restart. Install failures are shown once on the next normal startup with retained-data guidance. The helper starts only after that explicit action and waits for normal app shutdown; it never terminates the old app. Runtime and installation leases reject competing processes, including processes using different data roots with the same installation.

The first updater-capable version must be installed manually. Already published unsigned ZIPs cannot be silently installed: the app provides the GitHub link and preserves the current installation. Automatic installation starts working only once a subsequent release includes the contract below and is signed with the matching key. Nothing in this change publishes a release.

## Authentication contract

Release assets are `update-manifest.json`, raw binary `update-manifest.sig`, and `ClassicWindowsIPTVPlayer-vVERSION-win-x64.zip` (the exact tag, including optional lower-case v, determines the package name). The established repository is `cyrusthelittle/classic-windows-iptv-player`; older manually downloadable asset names remain usable through the release page.

The signature is RSA with at least 3072 bits, SHA-256, PSS, over the **exact bytes** of the manifest. Core embeds the public `UpdateTrust.pem`; both Windows and the external helper use that compiled resource. The helper has no command-line key/path/trust override. A missing or different key fails closed. `UpdateTrustPath` is an MSBuild-time resource override for isolated fixture builds, never a runtime trust input.

JSON property names are PascalCase: Format=1, Repository, Tag, Version, Runtime=`win-x64`, Package, PackageSize, PackageSha256, DataSchema=2, and Files. Each Files record contains Path, Size and Sha256. Version must exactly match the offered numeric release tag, exceed the caller's current version and retain the current saved-data schema. No prerelease suffixes are supported for installation. The manifest is at most 1 MiB, signature at most 1 KiB, compressed package at most 1 GiB, expanded files at most 2 GiB/20,000 files. Hashes are hexadecimal SHA-256.

ZIPs contain files only with forward-slash relative paths. Exact size/hash and complete file-list equality are checked, including case-insensitive duplicates. Traversal, Windows reserved names/ADS, links/reparse paths, explicit directory entries, arbitrary executables and saved-data paths are refused. Required standalone files are `Classic Windows IPTV Player.exe`, `ClassicWindowsIptvPlayer.Updater.exe` and `ClassicWindowsIptvPlayer.Core.dll`. Application/native DLLs, PDBs, icon/image assets, and deps/runtimeconfig JSON are supported; the self-contained runtime's exact `createdump.exe` and LibVLC's two existing `libvlc/win-x64/plugins/access/libbluray-{awt-j2se-,j2se-}1.4.0.jar` assets are allowed. Arbitrary JAR paths remain refused. Accounts, cache, logs, updates, Recordings, portable marker and arbitrary data/JSON are never valid payload files. New application asset types need an explicit reviewed contract change.

Downloads start at the exact repository/tag GitHub HTTPS asset path and accept at most five redirects, limited to that repository download path or `release-assets.githubusercontent.com`, with no userinfo/nondefault ports. Asset response sizes are bounded as they stream. The whole download has a fifteen-minute deadline; caller cancellation also interrupts package hashing/ZIP verification. The helper independently rechecks the compiled-key signature and locked package, then extracts to a fresh private apply directory with its own five-minute verification deadline. It rechecks each locked extracted stream immediately before installation.

## Local release tooling

Run commands from public. Never put the private signing output, invented accounts, fixture credentials or normal user data into the repository/package. `keygen` refuses existing outputs and prints no key bytes. The private output is PKCS#8 protected by Windows current-user DPAPI with separate signing entropy; it requires the same Windows user/machine to sign. Retain a secure backup of that protected file and public resource plus the Windows user's DPAPI recovery material. There is no plaintext export command. Losing the private key requires an explicitly planned trust-key transition delivered by a manually installed build; replacing it without updating shipped trust prevents automatic updates.

```powershell
dotnet run --project tools/ClassicWindowsIptvPlayer.ReleaseSigner -c Release -- keygen C:\OUTSIDE-PUBLIC\NEW-release-signing.dpapi src\ClassicWindowsIptvPlayer.Core\UpdateTrust.pem
# keygen is only for a new key; never repeat against an existing trust resource.
dotnet publish src/ClassicWindowsIptvPlayer.Windows -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o C:\FRESH-PAYLOAD
# Windows's publish target also publishes the self-contained single-file helper with native libraries embedded into that folder.
dotnet run --project tools/ClassicWindowsIptvPlayer.ReleaseSigner -c Release -- sign C:\OUTSIDE-PUBLIC\release-signing.dpapi C:\FRESH-PAYLOAD C:\FRESH-SIGNED-OUTPUT v0.8.2
```

Choose fresh, separate absolute directories. The signer includes all payload files and rejects forbidden user-data/seed files rather than omitting them silently. It does not upload or overwrite release assets and validates the resulting manifest/package with the production verifier. For a local authenticated fixture, use a newly generated fixture key outside public, build Core/helper with its public resource into isolated artifact/output directories, and sign an invented payload with the same tool. Production builds use the real public resource. Keep the current installed helper and Core DLL together; startup copies this existing helper to its own runner (the self-contained helper embeds Core and native runtime files; development runtimeconfig/deps/DLL files are copied when present) before replacing installed files. Self-contained publication supplies its runtimeconfig and runtime without requiring an installed .NET runtime.

The existing BUILD_WINDOWS_RELEASE.bat creates the manual package and separately adds its tracked free-to-air account seed. That seed is deliberately outside this signed-update contract: sign a fresh publish payload before adding any manual-package seed. The script now publishes a self-contained non-single-file app/helper so the required files remain independently installable.

## Apply, rollback and recovery

A job under the pinned data root's updates folder records StageDirectory, InstallDirectory, DataRoot, ParentProcessId, CurrentVersion and Tag. `ClassicWindowsIptvPlayer.Updater.exe --apply ABSOLUTE-update-job.json` waits for that process to exit, acquires the install/data leases, verifies again, completes application-only backups, and durably writes `.update-pending.json` before replacing any file. Replacements use flushed temporary files and per-file rename. Original application backup bytes are hashed; restoration hashes and copies each source through the same locked stream. Old unlisted application files remain in place. User-data files and recording files never participate in backup/replacement/deletion.

The durable marker remains throughout verification of the installed app. A special noninteractive probe child opens protected settings, creates the actual unshown Login/Main XAML and native LibVLC/MediaPlayer without providers, streams, recording or user interaction, writes ready and exits successfully. The helper requires both success and the exact acknowledgment before moving the marker to retained history and launching the normal app with the same absolute `CYRUS_IPTV_DATA_ROOT`. Only a stuck noninteractive probe may be terminated. The probe does not establish painted UI, actual playback, network interoperability or user interaction. Same-schema-only installation permits immediate binary rollback without feeding a newer schema to an old app; future schema-changing updates must add the separate compatible-snapshot policy in SAVED_DATA.md.

If verification/apply/probe fails, old application files are restored and the old app is relaunched when restoration succeeds. Failed restoration keeps the blocking marker and backups; no mixed installation is relaunched. Power interruption is recoverable through the retained job and copied runner, but is not silently repaired by normal startup. After resolving permissions/file locks, run the copied runner with `--recover ABSOLUTE-update-job.json`; it holds both leases, validates/restores the recorded backups, removes the marker and relaunches the old app. Keep all stage/journal/backup files until recovery succeeds. `update-result.txt` under the stage records failure guidance; native/rendered recovery UI remains a release acceptance check.

Retained download/application backup artifacts are not automatically pruned yet. They contain application assets, not copied account state. Update backups are separate from Step 30's protected saved-data migration snapshots. Preserve later recordings and newer saved data during any manual rollback.
