# Core regression checks

Step 16 adds four organization checks. They use isolated temporary app data and invented URLs to verify persisted channel/group rename, hide and order across a refreshed catalog, stable item identity, favorite/folder ordering, secret-free export with preview/import and protected local backup/restore. They do not render the WPF context menus or verify keyboard, Narrator or scaling behavior. An interactive Windows run with isolated app data is still required for those controls and for the account information presentation. Local backups are bound to the same Windows user profile by Windows data protection.

From the repository root, with the .NET 10 SDK installed:

```powershell
dotnet run --project tests/ClassicWindowsIptvPlayer.Core.RegressionTests --configuration Release
```

The runner prints PASS/FAIL for each check and exits nonzero on failure. It requires no test framework packages, network access, saved accounts, or provider credentials. Synthetic XMLTV fixtures use a fixed clock and the production streaming parser. Coverage includes adjacent fields, repeated/empty/unknown elements, channel aliases, timezone boundaries, invalid records followed by valid ones, guide windows, and cooperative cancellation between reads.

The runner also links the production tuner retry policy without loading LibVLC. Five checks cover initial connection failure limits and delay cadence, a 31-second live drop receiving a fresh retry budget, the exact 30-second boundary, Stop canceling a pending retry, and a newer tune canceling or superseding recovery. These deterministic checks do not verify native playback, stream event delivery or video surface handoff.

Eleven diagnostic checks use invented credentials to exercise query strings, stream paths, malformed URLs, percent-encoded names and values, nested exceptions, source summaries, the real log writer and in-memory source-probe failures. They do not exercise WPF crash dialogs/files, the Stream information dialog, or native LibVLC error output; those paths need a manual run with a controlled local stream and an isolated data directory.

Five playback/browse checks link the production state class and use only synthetic A/B channels and opaque tune requests. They verify that selection does not change the playing channel or source, rapid A/B/A and same-channel retunes reject stale callbacks, and Stop rejects late events. They do not exercise WPF controls or native LibVLC playback; use controlled local streams for those paths.

Seven storage checks use a unique temporary data directory per case. They exercise the production atomic save/recovery path, Windows user-scoped protection, legacy JSON/GZIP migration, retained unmatched favorites, account-scoped series collisions, stable keys after title and credential changes, secret-free organization export, and explicit failure when both settings copies are corrupt. All credentials and URLs are invented. The checks do not exercise WPF recovery dialogs or migration from an actual user's data; use an isolated Windows profile/data directory for that smoke test.

Six account editing checks exercise the production draft session with invented account URLs. They cover switching between unfinished entries, cancel and reopen against an isolated settings file, validation before any state mutation, committing edits without changing the active account, deferred removal, and field-specific URL/credential errors. Focused Enter behavior, dialogs, and playback preservation still need an isolated WPF run with a controlled local stream.

Five provider checks use an in-memory synthetic HTTP handler. They cover comma-bearing M3U names with quoted comma attributes, HTTP and empty playlist failures, partial Xtream API fallback, optional series failure retaining M3U episodes, and cancellation during a slow request. WPF stage/actions, account switching, cache persistence across restart, and native playback still need an isolated Windows run with a local fixture server.

Six playback mechanics checks use synthetic positions and slider values. They exercise the production seek conversion shared by mouse and keyboard, VOD recovery near the last confirmed point including backward seeking and invalid samples, request isolation, and the normal-completion decision. They cannot prove WPF focus/drag behavior or LibVLC teardown. Before release, use only a controlled local video fixture and isolated app data to check seek from the slider by mouse and keyboard, fullscreen focus/drag/context menu visibility, repeated tune/Stop/shutdown, recovery from a forced VOD error after seeking, ordinary VOD completion, and a stream that stalls without a terminal event. Inspect for hangs and detached native windows.

Ten library navigation checks use invented catalog, search and media-library state against the production empty-state/reset and position-history logic. They cover retry guidance for a missing library, search clear/reset guidance, favorite and recent guidance, reset availability, distinct media scopes, restored filters/selection/scroll after switching libraries, selected identity after result reorder, and repeat selection of the current media category. WPF layout, focus, scaling, actual ListBox scroll restoration and native playback controls require an isolated interactive Windows check.

Four large-library checks use 100,001 invented entries against the production search index and lazy list source. They verify tail reachability beyond the former 50,000 cutoff, multi-term/kind matching, cancellation and deferred row creation. The runner prints process-local index and search timings; these exclude cache loading and WPF rendering, so interactive performance remains a manual measurement.

Four guide foundation checks use invented XMLTV across the October 2026 daylight-saving fallback. They exercise manual mapping, programme boundary correction, recoverable protected account-scoped cache, and cancellation. They do not render the selected-channel panel or prove a provider's XMLTV compatibility. Check those with a local fixture endpoint and isolated Windows data before release.

Six guide grid checks use invented XMLTV to verify both occurrences of the fallback hour, absolute two-hour navigation, later-date retention, account time correction, title/description search and lazy row creation. A 100,001-programme search result verifies that rows are created only as requested. They do not render WPF, measure row recycling or verify keyboard/Narrator behavior; those require an isolated interactive Windows run.

Five viewing-history checks use invented movie and episode URLs in isolated temporary settings directories. They cover persisted position, duration and watched state after reopen, account isolation and account-editor merge, completion, dismissal and Start Over, season/episode order with watched-skip behavior, identifiable M3U episode siblings, and chronological Recent including a resolved episode after settings backup recovery. They do not run LibVLC or render the WPF Resume, season picker, Continue and next-episode controls; those require an interactive run with a controlled local video fixture.

Seventeen step-18 recording checks use invented accounts and temporary directories. They verify the shared connection-allowance parse and local stream budget (add/replace, confirmed unknown allowance, double release, leak visibility, local ceiling), account-scoped recording index persistence with versioned/DPAPI/GZIP files and backup recovery, secret-free index fields, free-space thresholds, Windows-safe naming and collisions, unsupported-source refusal, programme metadata capture at the actual start instant, terminal outcomes, and combined destination/space/name/connection decisions. The separate Windows native fixture runner generates a silent WAV in the temporary directory and serves its first bytes from a loopback HTTP listener before stalling. Run `dotnet run --project tests/ClassicWindowsIptvPlayer.NativeFixtureChecks --configuration Release --no-restore` after restoring from locally available packages. The step 14 ownership runner is `tests/ClassicWindowsIptvPlayer.VideoOwnershipChecks`. Build it with `dotnet build tests/ClassicWindowsIptvPlayer.VideoOwnershipChecks/VideoOwnershipChecks.csproj -c Debug --nologo`, then launch `VideoOwnershipChecks.exe` in an interactive Windows session. It generates its own local changing-color AVI and saves `ownership.log` plus `main-*`, `mini-*`, `fullscreen-*`, `returned-*` and `stopped-*` PNGs beside the executable. It checks the live LibVLC drawable, persistent child HWND, root window after host moves, nonblank captured frames, detached VLC windows, repeated play/Stop and shutdown. Review the captured images as well as the PASS line. This is an isolated WPF host probe; it does not exercise the application's account/catalog controls. Five additional synthetic checks cover the ownership guard's accept/reject decisions without claiming native rendering.

The parser accepts timestamps with minute or second precision (12 or 14 digits), numeric offsets, and UTC/GMT/BST zone names. A missing zone means UTC; unknown zone names are skipped. Explicit stop times are required, and DTD declarations remain prohibited. These checks cover the supported subset, not full XMLTV compliance. Repeated text fields retain their first nonempty value. Cancellation does not interrupt an underlying stream read that has stalled; network body deadlines are a separate roadmap step.

## Phone remote production-window harness

This verifies filter feedback, accessibility pressed states, search flushing, ordered commands and HTTP error feedback; it is not a rendered-layout test. ## Step 19 scheduled recording

Scheduled jobs are account-scoped and store channel/programme identity, UTC programme and padded capture windows, an output path, status and a safe reason; they never store provider URLs or credentials. Programme details in the guide provide the scheduling action; the schedule manager lists, refreshes and cancels jobs. Overlaps, restart recovery, expired jobs, disk-full outcomes and cancellation have explicit states. Conflict classification uses an account-scoped O(n log n) interval sweep, avoiding an all-pairs scan during periodic checks.

Safety boundary: a scheduled job only attaches to an already-playing, matching supported shared-HLS source. The scheduler never tunes, stops or replaces playback, opens a second provider stream, or wakes Windows. If the matching channel is not already playing, the job remains retryable during its capture window and is marked missed when the window expires. Sleep/resume and real-provider compatibility still need manual verification.

Core validation passes **13/13 scheduled-recording checks**, including a 20,000-job overlap case. The isolated synthetic WPF/LibVLC fixture passes **56/56 checks**, including a coordinator job reaching `Recording` then `Completed` with a flushed 4,609,384-byte file while the same player and upstream HLS poller remain active and each segment is fetched once. Startup cancellation also completes promptly without leaving a file or consumer. The Windows Release build passes with 0 warnings/errors. Evidence is in `%TEMP%\cyrus-recording-ui-fe6acd439fa24fffae1a21218d8296d8\evidence.txt`.

To manually inspect the UI, launch `src/ClassicWindowsIptvPlayer.Windows/artifacts/shared-stream-recording-test-20260929/Classic Windows IPTV Player.exe` from its staged folder. That folder is isolated from normal settings and currently contains no `accounts.json`; only create a test account for provider testing if authorized. For an actual scheduled capture, the same account/channel must remain playing across the requested window.

## Opt-in crash reports and feedback

The Core regression suite exercises the feedback queue with an injected local `HttpMessageHandler`; it does not contact the configured webhook. It checks crash payloads and both feedback payload forms: `{ type, message }` when logs are excluded, and `{ type, message, log }` when the selected-by-default Feedback checkbox includes redacted logs. It also checks HTTPS endpoint validation and protected settings, DPAPI-protected queue persistence, crash-log redaction, UTF-8 byte limits, no-endpoint behavior, and failed delivery followed by explicit retry with the log choice retained. Crash-session marker checks distinguish normal shutdown from an interrupted session and confirm session logs are retained. Interactive production-app checks of the checkbox, next-launch crash prompt, its Send/Later/Don't send actions, and the Feedback menu's send/retry display remain manual.
